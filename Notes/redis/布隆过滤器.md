# 布隆过滤器

布隆过滤器用一段位数组和多个哈希函数，判断一个元素**是否可能加入过**。它不保存完整的元素值，适合在查询缓存、数据库之前拦截明显不存在的 ID。

## 一个能手算的例子

假设位数组只有 **8 位**，编号为 `0～7`。每个商品 ID 经过两个演示用哈希函数，得到两个位的位置：

```text
h1(ID) = ID 除以 8 的余数
h2(ID) = (ID 整除 8) 再除以 8 的余数
```

这两个简化算式只为方便手算；真实系统应使用合适的哈希函数和更多位。

### 1. 加入存在的商品

数据库中有商品 `1001` 和 `1010`。开始时，所有位都是 `0`：

```text
位置： 0 1 2 3 4 5 6 7
位值： 0 0 0 0 0 0 0 0
```

加入 `1001`：

```text
h1(1001) = 1001 % 8 = 1
h2(1001) = (1001 整除 8) % 8 = 125 % 8 = 5

位置： 0 1 2 3 4 5 6 7
位值： 0 1 0 0 0 1 0 0
```

加入 `1010`：

```text
h1(1010) = 1010 % 8 = 2
h2(1010) = (1010 整除 8) % 8 = 126 % 8 = 6

位置： 0 1 2 3 4 5 6 7
位值： 0 1 1 0 0 1 1 0
```

布隆过滤器现在只保存这 8 个位，不保存 `1001`、`1010` 本身。

### 2. 查询不存在的商品 9999

查询时使用**相同的两个哈希函数**：

```text
h1(9999) = 9999 % 8 = 7
h2(9999) = (9999 整除 8) % 8 = 1249 % 8 = 1

位置 7 的位值是 0；位置 1 的位值是 1。
```

只要有一个对应位为 `0`，就能确定 `9999` **没有加入过**，可以直接拦截这次查询，无需访问数据库。

### 3. 查询另一个不存在的商品 1009

```text
h1(1009) = 1009 % 8 = 1
h2(1009) = (1009 整除 8) % 8 = 126 % 8 = 6

位置 1 的位值是 1；位置 6 的位值也是 1。
```

但 `1009` 实际没有加入：位置 `1` 是 `1001` 设为 `1` 的，位置 `6` 是 `1010` 设为 `1` 的。布隆过滤器无法区分这些 `1` 来自谁，只能回答 **“1009 可能存在”**，让后续缓存或数据库继续确认。这叫**误判为存在**。

## 判断规则

| 对应位置的位 | 结论 | 后续动作 |
| --- | --- | --- |
| 至少一个是 `0` | 确定没有加入过 | 可直接拦截 |
| 全部是 `1` | 可能加入过，也可能误判 | 继续查询确认 |

在过滤器已正确加入所有现存 ID、且数据保持同步的前提下，已加入的元素不会被误判为不存在。位数组越拥挤，误判为存在的概率通常越高。普通布隆过滤器也不能直接把某个元素对应的位清零，因为这些位可能同时被其他元素使用。
