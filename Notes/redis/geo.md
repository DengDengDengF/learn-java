# Redis GEO：附近门店查询

Redis GEO 用来保存地点的经纬度，并查询某个位置附近的地点。坐标顺序是 **经度、纬度**。

## 实例 Demo

```redis
# 添加门店：经度 120.15°，纬度 30.28°
GEOADD stores 120.15 30.28 store:001

# 以 (120.16, 30.27) 为中心，查询 3 公里内的门店
# ASC 按距离从近到远排序；WITHDIST 同时返回距离
GEOSEARCH stores FROMLONLAT 120.16 30.27 BYRADIUS 3 km ASC WITHDIST
```

查询结果会包含 `store:001`，距离约为 **1.47 km**。`stores` 是存放门店位置的键，`store:001` 是门店标识。Redis 只会查询已经通过 `GEOADD` 加入的地点；店名、地址等资料可以另存到 Hash，再按门店标识读取。

## 两点在哪里

两点都在中国杭州附近，地球上的大致位置如下（仅作示意）：

```text
                 北极
                  ●
             .-----------.
          .-'             '-.
         /                   \
        |       中国东部  ★    |  ← 两点所在区域
         \                   /
          '-.             .-'
             '-----------'
                  ●
                 南极
```

把 ★ 附近放大：纬度越高越靠北，经度越大越靠东。

```text
                       北
                       ↑
纬度 30.28°     ● 门店 (120.15, 30.28)
                 │╲
                 │ ╲  约 1.47 km
                 │  ╲
纬度 30.27°       └───● 查询中心 (120.16, 30.27)
                       → 东

               经度增加 0.01°
```

所以门店在查询中心的**西北方向**。

## 距离怎么估算

这两个地点很近，可以把局部地表近似看成平面：

```text
东西距离 ≈ 0.01 × 111.2 × cos(30.28°) ≈ 0.96 km
南北距离 ≈ 0.01 × 111.2                ≈ 1.11 km
两点距离 ≈ √(0.96² + 1.11²)            ≈ 1.47 km
```

这里的 `111.2 km` 是地球上纬度相差 1° 时的大致距离。经线向两极靠拢，所以经度方向还要乘纬度的余弦。Redis 实际按球面距离计算，并非直接使用上面的平面近似；得到的是地理距离，不是驾车或步行路线距离。

Redis 会先用 GeoHash 缩小候选地点范围，再计算候选地点的距离，筛出 3 公里内的门店。`ASC` 最后按距离排序。
