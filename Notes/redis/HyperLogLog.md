# Redis HyperLogLog

## 它解决什么问题

HyperLogLog（HLL）用于**估算不同元素的数量**，也叫基数估计。例如统计一天有多少个不同用户访问网站（UV）：

```redis
PFADD visitors:today user1 user2 user1
PFCOUNT visitors:today
```

这里加入了三次，但只有两个不同用户，`PFCOUNT` 通常返回 `2`。`PFADD` 的返回值表示内部状态是否发生变化，**不是**新增用户数。

HLL 不保存完整的用户 ID，因此不能列出用户，也不能判断某个用户是否来过。需要精确去重或查询成员时，用 Set。

## 为什么看第一个 1 的位置

先对每个用户 ID 做哈希，把结果看作一串近似随机的二进制位：

```text
userA -> 1...        第一个 1 在第 1 位
userB -> 001...      第一个 1 在第 3 位
userC -> 0001...     第一个 1 在第 4 位
```

位置从 **1** 开始数。第一个 `1` 越靠后，这种哈希结果越罕见。例如，恰好以 `0001` 开头的概率是 `1/16`。观察到罕见结果，通常意味着已经见过一定数量的不同哈希值。不过单个结果有偶然性，不能只靠它估算总人数。

## 分组后怎么记录

### 1.方便解释

HLL 用哈希值的一部分选组，再看**剩余部分第一个 `1` 的位置**。每组有一个寄存器，只保留该组见过的最大位置；空组记 `0`。下面用 **4 组**和示意哈希值演示（真实 Redis 使用更多组）：

| 加入 | 假设的哈希结果 | 分组 | 第一个 `1` 的位置 | 加入后四组的记录 |
| --- | --- | ---: | ---: | --- |
| A | `00 \| 101...` | 0 | 1 | `[1, 0, 0, 0]` |
| B | `00 \| 110...` | 0 | 1 | `[1, 0, 0, 0]` |
| C | `00 \| 001...` | 0 | 3 | `[3, 0, 0, 0]` |
| D | `01 \| 01...` | 1 | 2 | `[3, 2, 0, 0]` |
| E | `10 \| 01...` | 2 | 2 | `[3, 2, 2, 0]` |
| F | `11 \| 1...` | 3 | 1 | `[3, 2, 2, 1]` |

`|` 左边只用于选组，位置从右边的第一位开始数。A 和 B 是两个不同用户，却都落入第 0 组，且位置都是 `1`，所以加入 B 后仍记 `max(1, 1) = 1`。C 的位置是 `3`，加入后第 0 组才更新为 `max(1, 3) = 3`。如果再加入一次 A，哈希结果相同，四组记录都不会变。

我们知道表中有 **6 个不同用户**，但 HLL 最后只保存 `[3, 2, 2, 1]`，无法从第 0 组的 `3` 还原出 A、B、C 三个人。因此它只能估算人数；新用户没有改变任何寄存器时，也可能导致低估。

### 2.实际取位

Redis 先把元素计算成 **64 位哈希值**，取其中的**低 14 位**作为组编号，因此共有 `2^14 = 16,384` 组（编号 `0` 到 `16,383`）。随后从剩余的 **50 位**的低位方向开始，找第一个 `1` 的位置，并用这个位置更新对应组的寄存器。

```text
64 位哈希值 = 50 位（找第一个 1）| 14 位（选组）
                                  ↑ 实际从剩余部分靠近选组位的一端开始找
```

上面的 4 组表格把选组位画在左边，仅用于演示分组过程；它不表示 Redis 实际取的是高位。组数由 Redis 的实现固定，不会随着加入的用户数变化。

## 怎么得到估算数量

HLL 综合所有组的寄存器值 `M₁ ... Mₘ`，计算原始估算值。其核心形式是：

```text
原始估算值 = αₘ × m² / (Σ 2^(-Mᵢ))
```

其中 `m` 是组数，`αₘ` 是修正系数。一个组观察到的最大值越大，对应的 `2^(-Mᵢ)` 越小，推算的元素数量倾向于越多。公式同时使用所有组，减少单组偶然出现极端结果的影响。Redis 还会对小基数等情况做修正，再由 `PFCOUNT` 返回最终的**整数估算结果**。上面的 4 组示例只用于理解记录过程，不能直接当作 Redis 的实际返回值。

## 特点与适用场景

- 内存占用很小：Redis 的 HLL 在完整表示下约占 12 KB，即使统计大量不同元素也不会随人数线性增长。
- 结果有误差：Redis HLL 的标准误差约为 `0.81%`，不能当作精确计数。
- 适合统计 UV、独立设备数等只关心大致去重数量的场景。
- 如果还要知道“谁来过”，或者需要精确人数，应使用 Set 等能保存成员的数据结构。

**一句话：**HLL 保存的是多个分组中哈希结果的统计特征，再根据这些特征估算去重数量；它不保存完整成员列表。
