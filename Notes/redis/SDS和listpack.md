# SDS 和 listpack 的区别

**SDS 保存一段字符串字节；listpack 把多个元素紧凑地保存在一块连续内存中。** 它们解决的问题不同，并非两种互相替代的字符串实现。

| 对比 | SDS | listpack |
| --- | --- | --- |
| 存储内容 | 一段字符串字节 | 多个元素，元素可以是字符串或整数 |
| 长度信息 | 头部的 `len` 记录当前字符串的字节长度 | 头部记录整体字节数；每个元素末尾有自身长度信息，便于反向遍历 |
| 修改特点 | 可利用预留空间追加；缩短时可保留空闲空间 | 插入、删除或改变元素大小时，可能需要移动后面的字节 |
| 常见用途 | 键名、字符串值等 | 小型 Hash、ZSet，以及 quicklist 节点内部 |

## 长度字段容易混淆

```text
SDS：      [len][容量等信息][hello]
           len = 5，表示字符串内容有 5 个字节

listpack： [整体头部][元素 A：内容...自身长度][元素 B：内容...自身长度][结束标记]
```

SDS 读取字符串长度时，可以直接读取头部的 `len`。listpack **元素末尾**的长度信息用于从该元素向前找到上一个元素，并不是整个 listpack 的长度。listpack 整体占用的字节数记录在头部；头部也有元素个数字段，但在某些情况下仍需遍历才能确定元素个数。

## 例子

`"hello"` 是一个字符串，可以用一个 SDS 保存。`[name, "Li", age, 20]` 是四个元素，可以紧凑地放在一个 listpack 中。这里的方括号仅用于示意，不表示 Redis 实际存储了这些标点。

两者可以同时出现：一个 Hash 的 Redis 键名可以由 SDS 保存，而该 Hash 的字段和值可以存放在 listpack 中。小型数据使用 listpack 能节省内存；数据变大后，Redis 可能转换为其他底层编码。
